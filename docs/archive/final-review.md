## 요구사항 (2026-11-06 사용자 지시)

1. 모든 과정에 GPT 평가를 넣는다. 평가와 판정은 Claude와 GPT가 같은 구조로 한다.
2. 평가 페르소나를 직접 세운다. 한쪽 경향으로 치우치지 않게 서로 견제하는 페르소나로 구성한다.
3. 번역 말투(AI가 쓴 티, 어색한 말투, 문법)를 평가하고 고친다. UI는 UI답게, 설치 프로그램은 설치 프로그램답게.
4. 과정을 기록하고 기록을 근거로 진행한다.
5. 한국어 설치 안내에서 NVDA 브리지 설치 방법이 빠진 원인을 조사하고 방지책을 만든다.
6. 확인 창 없이 이어서 진행되게 한다(위험한 작업 제외).

## 페르소나

`tools/review/prompts/lens-persona-*.md`. 다섯 명이 서로의 치우침을 견제한다.

| 페르소나 | 보는 것 | 치우치기 쉬운 쪽 | 견제하는 페르소나 |
|----------|---------|------------------|-------------------|
| 스크린리더 숙련 게이머 | 들었을 때 바로 알아듣는가, 길이, 반복 발화 | 지나친 축약 | 처음 쓰는 사용자 |
| 한국 WoW 오래 한 플레이어 | 게임 공식 용어, 한국 서버에서 실제로 쓰는 말 | 은어·줄임말 | 교정 편집자, 처음 쓰는 사용자 |
| 한국어 교정 편집자 | 문법, 맞춤법, 띄어쓰기, 번역투, 조사 | 딱딱한 규범 문장, 장황함 | 숙련 게이머, UI 라이터 |
| UI 문구 라이터 | 문구 종류별 문체(버튼·라벨·상태·안내·오류), 일관성, AI가 쓴 티 | 원문을 벗어난 다듬기 | 교정 편집자(원문 충실), 공통 규칙 |
| 처음 쓰는 사용자 | 처음 듣는 사람이 이해하는가, 모호한 말 | 설명을 덧붙이려 함 | 숙련 게이머 |

모든 페르소나에 공통으로 적용하는 제약은 다음과 같다. 원문의 뜻을 보존하고, `docs/decisions.tsv`, `docs/glossary.tsv`, 게임 공식 용어, 서식 지정자를 지킨다. 취향 차이는 결함이 아니다. 지금 번역이 이미 좋으면 지적하지 않는다.

## 절차

`docs/review-process.md`를 그대로 따른다. 다른 점은 2단계 평가자가 관점 4개 대신 페르소나 5명이라는 것뿐이다.

1. 묶음 만들기: UI는 `tools.review.build_batch`, 설치 프로그램은 `tools.installer_loc batch`
2. 평가: 묶음마다 페르소나 5명 × (Claude, GPT) = 10명, 서로의 결과 비공개 (`full.js`, `lenses` 인자)
3. 반박: 번역자. 두 회사가 같은 항목을 지적하면 반드시 수용
4. 판정: 반박된 지적은 Claude와 GPT가 따로 판정, 일치할 때만 확정
5. 반영: `tools.review.decisions` → `apply.tsv` → `tools.sync_locale` (UI), `tools.installer_loc apply` (설치 프로그램)
6. 회귀 확인: 바뀐 항목만 Claude 1 + GPT 1 (`regression.js`). 순환 최대 2회, 남으면 `docs/decisions.tsv` 2026-11-06 기준(근거가 글자 그대로 확인되는 것만 반영)
7. 기계 검사 `uv run pytest -q`, 설치 프로그램 빌드와 자체 검사, 테스터 폴더 다시 만들기
