# WowVision 한국어 번역 지침

WowVision 원문(`../wowvision-ko/vision-locale/enUS/*.lua`)을 같은 저장소의 `koKR/*.lua`로 번역할 때, 그리고 영어 설명서를 한국어로 옮길 때 따르는 규칙입니다. 번역 파일은 vision-locale 저장소(원본의 포크)의 `main` 브랜치에 커밋하고, 이 저장소(wowwork)에는 도구와 기록만 둡니다. 각 규칙을 정한 경위와 날짜는 `docs/decisions.tsv`에 있습니다.

## 파일 형식

- 파일 이름은 enUS와 같습니다. 첫 두 줄은 반드시 다음과 같습니다.

```lua
local L = LibStub("AceLocale-3.0"):NewLocale("WowVision", "koKR")
if not L then return end
```

- enUS의 키를 하나도 빠짐없이, 같은 순서로 옮깁니다. `--` 주석 줄과 빈 줄도 원문 위치에 그대로 둡니다.
- 값은 항상 한국어 문자열입니다. `true`를 쓰지 않습니다. enUS가 `L["EditBox"] = "Edit"`처럼 값을 따로 가진 경우에는 키가 아니라 그 값을 번역합니다.
- 큰따옴표와 백슬래시는 Lua 규칙대로 이스케이프합니다.
- 같은 키는 파일이 달라도 번역이 하나입니다. AceLocale은 키 하나에 값 하나만 가지므로, 다른 파일에 이미 있는 키는 그 번역을 따릅니다. 예: `Direct`는 음성 방식(`speech.lua`)과 길 안내 창(`navigation.lua`)이 함께 사용하므로 둘 다 "직접"입니다.
- 검증: `uv run pytest -q`가 키 누락, 원문에 없는 키, 빈 값, 서식 지정자 불일치, Lua 문법 오류를 잡습니다.

## upstream 업데이트 절차

원본의 새 릴리스를 따라갈 때의 순서입니다. 명령은 wowwork 폴더에서 실행합니다.

1. 원본을 받습니다: `git -C ../wowvision-ko/WowVision fetch upstream --tags`와 `git -C ../wowvision-ko/vision-locale fetch upstream`.
2. 따라갈 원본 릴리스를 병합하고 원본 테스트를 돌립니다.
   - WowVision `ko`에는 릴리스 태그를 병합합니다: `git -C ../wowvision-ko/WowVision merge <태그>`.
   - vision-locale `main`에는 그 태그의 `locale` 서브모듈 커밋을 병합합니다. 커밋은 `git -C ../wowvision-ko/WowVision ls-tree <태그> locale`이 보여 줍니다.
   - 원본 테스트 전에 WowVision 폴더에서 `git submodule update --init`과 `luajit tools/wownav-pack.lua`를 실행합니다. 테스트는 git에 없는 생성물 `mapdata/WowNavPacked/`를 읽기 때문에, 이 묶음이 낡으면 WowNav 경로 테스트가 실패합니다.
   - 원본 테스트는 WowVision 폴더에서 `luajit tools/headless-tests.lua`로 돌립니다. 결과 없이 종료 코드 139로 끝나면 다시 실행합니다.
3. `uv run python -m tools.game_terms`로 게임 용어 목록을 업데이트합니다. 번역할 때 이 목록의 공식 용어를 씁니다.
4. `uv run python -m tools.sync_locale`을 실행합니다. 번역이 없는 키가 있으면 파일을 쓰지 않고 `cache/missing.tsv`를 만듭니다. 키는 그대로인데 영어 값이 바뀐 키도 `old_en` 열과 함께 이 목록에 올라옵니다. 비교 기준은 마지막 동기화 때의 영어 값(`state/enUS.tsv`)입니다.
5. `cache/missing.tsv`의 `ko` 열을 채우고 검수한 뒤 `uv run python -m tools.sync_locale cache/missing.tsv`를 실행합니다. 줄 순서와 주석은 enUS를 따르고, 원문에서 사라진 키는 빠지며, `modules.xml`은 enUS 것을 복사합니다. 그다음 `uv run pytest -q`로 검증합니다.
6. 한국어 값이 바뀐 키가 있으면 4·5단계의 `tools.sync_locale`이 한국어 설명서의 화면 문구 인용도 새 값에 맞춥니다. 바꾼 값 바로 뒤의 조사(을/를, 이/가, 은/는, 와/과, 으로/로)도 새 값의 받침에 맞춥니다. "판단 필요"로 나온 곳은 영어 설명서와 대조해 직접 고칩니다. 그다음 `uv run pytest -q`로 검증합니다(설명서 검사 `tools.manual check`가 포함되어 있습니다).
7. 설치 프로그램에 넣는 koKR이 낡으면 `tests/test_installer_loc.py`가 실패합니다. `uv run python -m tools.installer_loc payload`로 다시 만들고 `docs/builds.md` `## 다시 만드는 법`대로 빌드합니다.

## 서식 지정자

- `%s`, `%d` 같은 지정자는 개수와 종류를 원문과 똑같이 유지합니다.
- 한국어 어순 때문에 순서를 바꿔야 하면 `%2$s`처럼 위치 지정을 사용합니다(WoW의 `format`이 지원합니다).
- 숫자 사이의 `of`("1 of 5")는 영어 `of`를 그대로 둡니다. 코드가 이어 붙이는 `L["of"]`와 서식 문자열 안의 `of`(`Page %d of %d` → `페이지 %d of %d`)가 모두 해당합니다.
- 지정자 바로 뒤에 받침에 따라 달라지는 조사(을/를, 이/가, 은/는, 와/과, 으로/로)를 붙이지 않습니다. 문장 구조를 바꿔 피합니다. 예: `Whisper %s` → `%s에게 귓속말`(에게는 받침과 무관). 피할 수 없는 경우는 보고 목록에 올립니다. `tests/test_kokr.py` `test_no_batchim_josa_after_spec`이 검사합니다.

## 용어

1. 인게임 용어가 최우선입니다. `cache/game_terms.tsv`에는 원문 문자열과 정확히 일치하는 게임 GlobalStrings의 공식 한국어가 있습니다(출처: wago.tools, 리테일 클라이언트). 일치 항목은 이 번역을 사용합니다. 후보가 `|`로 여러 개이면 문맥에 맞는 것을 고릅니다.
2. 정확히 일치하지 않는 문구도 그 안의 게임 용어(창 이름, 직업, 자원, 아이템 품질, 경매 용어 등)는 공식 한국어를 사용합니다. 필요하면 `cache/gs_enUS.csv`와 `cache/gs_koKR.csv`를 `BaseTag`로 대조해서 찾습니다.
   문맥이 우선입니다. 같은 문맥(같은 창, 같은 기능)의 공식 번역이면 그대로 따릅니다. 영어 문자열만 같고 다른 문맥에서 온 일치 항목이면 문맥에 맞게 번역합니다. 예: Comment는 공식 "하실 말씀"이 아니라 "의견", Merchant는 "상품 목록"이 아니라 "상인"으로 옮깁니다.
   행동 단축바 계열은 모두 "단축바"로 통일합니다(태세 단축바, 게임패드 단축바).
3. 뜻이 애매하면 원본 코드에서 키가 어떻게 쓰이는지 확인합니다. `../wowvision-ko/WowVision` 아래에서 `L["키"]`를 검색하고, 사용처가 여러 문맥이면 전부 셉니다. 모든 문맥에 맞는 말이 없으면 일부 문맥에만 맞는 말을 고르지 말고 공유 키 문제로 사용자 판단 목록에 올립니다. 예: `Disabled`는 사용처 16곳 중 14곳이 흐리게 표시된 버튼이고 2곳만 설정 끄기 상태입니다. 설정에 맞춘 "사용 안 함"을 쓰면 버튼에서 "수락 버튼 사용 안 함"으로 들립니다.
4. 고유 이름은 그대로 둡니다: WowVision, WowNav, WoW Forever, Battle.net, BattleTag.
5. 키보드 키 이름(Shift, Ctrl, Alt, Enter, Tab, Space 등)은 영어 그대로 둡니다.

## 문체

- 음성 알림과 상태 문구는 짧은 명사형으로 씁니다. 예: `combat started` → `전투 시작`, `combat ended` → `전투 종료`.
- 설정 이름과 메뉴 항목도 명사형입니다. 예: `Count Elite Enemies Only` → `정예 적만 세기`.
- 안내 문장(설명, 도움말)과 사용자에게 할 일을 지시하는 문장은 합니다체로 씁니다.
- 상태 알림은 원문이 마침표로 끝나는 완결 문장이어도 합니다체로 늘리지 않고 간결하게 씁니다. 원인과 결과는 "~해서 종료"처럼 잇습니다. 예: `Route ended outside the network's zones.` → "네트워크 지역 밖이라 경로 종료."
- 영어 복합어의 하이픈은 옮기지 않습니다. 예: `Auto-move` → "자동 이동".
- 컨트롤 종류 이름은 한국어로 옮깁니다. 예: Button → 버튼, Checkbox → 체크 상자, Dropdown → 드롭다운, Edit → 편집, Slider → 슬라이더.
- 원문의 대소문자 구분(`Combat`과 `combat`)은 한국어에서 의미가 없으므로 같은 번역을 사용해도 됩니다.
- 문장 부호는 한국어 문장에 맞게 다룹니다. 화면 문구 인용, 서식 지정자 주변, 코드가 이어 붙이는 구분자처럼 뜻이나 동작을 가진 기호는 원문대로 둡니다. 스크린리더가 기호를 어떻게 읽을지는 번역 판단에 넣지 않습니다. 그 판단은 사용자가 합니다.

## 보고 목록

번역하면서 아래에 해당하는 항목은 따로 모아 사용자 확인을 받습니다.

- 인게임 용어 후보가 여럿이라 고르기 애매한 것
- 조사 문제로 자연스러운 번역이 불가능한 것
- 원문 뜻을 확신하지 못한 것

## 설명서

`WowVision/docs/src/user/en`을 같은 저장소 `ko` 브랜치의 `docs/src/user/ko`로 옮길 때의 규칙입니다.

### 원문

- 원문은 영어판입니다. 독일어판은 뜻이 애매할 때 대조하는 참고본으로만 사용합니다.
- 개발자 문서(`docs/src/developer`)는 번역하지 않습니다.

### 용어

우선순위는 앞의 것이 이깁니다.

1. koKR 번역값. 원문에 로케일 문자열이 나오면 그 키의 한국어 값을 그대로 씁니다. 따옴표 안팎을 가리지 않습니다. 설명서를 번역하다 koKR 값이 어색하다고 판단되면 설명서만 다르게 쓰지 않고 koKR 값을 고칩니다. 듣는 말과 읽는 말이 갈라지지 않게 하기 위해서입니다.
2. 게임 공식 한국어. 위 `## 용어`와 같습니다(문맥 우선).
3. 확정 용어집 `docs/glossary.tsv`. 로케일에 없지만 설명서에 반복되는 말도 여기에 정합니다. 설명서에는 파일 단위로 적용됩니다. 원문 파일에 용어가 있으면 번역 파일에 정해진 번역이 한 번 이상 있어야 합니다. 같은 영어가 설명서에서 다른 뜻으로 쓰이면(키보드 초점의 focus) 그 용어의 예외 열에 `manual::*`을 적고, 설명서에서 쓰는 뜻은 더 긴 구절(`focus target`)로 따로 올립니다. 파일 사이에 같은 말이 갈렸다는 지적(예: 상호작용 키와 상호작용 단축키)은 고칠 때 용어집에도 올립니다.
4. 셋 다 없으면 보고 목록에 올리고 지어내지 않습니다.

### 번역하지 않는 것

키 이름, 슬래시 명령(`/wv`, `/focus1`), 인라인 코드와 코드 블록, URL, 파일 경로, 고유 이름(WowVision, WowNav, Sku, WoW: Forever, Battle.net, Discord). 링크 대상 경로도 바꾸지 않고 링크 텍스트만 번역합니다.

### 문체

- 습니다체로 씁니다.
- 독자를 부르는 "you"는 대부분 생략하고 주어를 프로그램으로 둡니다("X라고 안내합니다"). 원문 뜻이 달라지는 경우만 예외입니다. 프로그램이 실제로 하는 동작(읽다, 알리다, 열다)에만 그렇게 쓰고, 사람 동작에 빗댄 영어 동사(take, watch, step aside)는 기능을 설명하는 말로 옮깁니다.
- 원문 구조를 그대로 둡니다: 제목 수준, 표의 행과 열, 목록 항목 수, 링크 수. `uv run python -m tools.manual check`가 검사합니다.
- 낱말은 아래 `## 낱말 표`를 따릅니다. 설명서에서 자주 걸리는 것은 다음과 같습니다.
  - 바꾸다·바뀌다 → 변경하다·변경되다. 변경하다는 원문이 change일 때만 씁니다. switch는 전환하다, replace는 교체하다·대체하다, turn into는 변환하다·전환되다, swap은 맞바꾸다로 원문 뜻을 따릅니다.
  - 사람이 바꾸지 않고 저절로 달라지는 것(생명력, 위치)은 달라지다·변하다가 자연스럽습니다.
  - 관용 표현("마음이 바뀌면")은 "생각이 달라지면"처럼 뜻에 맞게 씁니다.
  - 화면·데이터 갱신 → 업데이트, 창이 뜨다 → 열리다, 포함 뜻의 들어가다 → 포함되다.
  - 따옴표 인용(화면 문구), 게임 공식 용어(오라 효과를 다시 거는 갱신, 버튼 이름)는 실물 그대로 둡니다. 따옴표 없이 쓰는 게임 이름(탭 "무엇이 바뀌었나요?")은 용어집에 올리면 검사가 실물로 인정합니다.
  - 바꾸다·바뀌다는 `tools.manual check`가 검사합니다.
- 원문에 없는 내용을 덧붙이지 않습니다. 한국 사용자에게 필요한 보충 설명은 보고 목록에 올립니다.
- 보존할 것과 자유로운 것을 가립니다. 보존: 사실, 조건과 한정어, 가능·의무·권장의 강도, 숫자와 키 이름, 화면 문구, 문서 구조. 자유: 문장 안의 어순과 구조, 주어 선택, 영어 관용구와 은유를 풀어 쓰기, 지시어("그 창", "그것")를 가리키는 명사로 되돌리기, 원문 문맥에서 이미 정해진 목적어 채우기. 뒤의 것들은 "원문에 없는 내용"이 아닙니다. 새 사실, 새 조건, 새 조언을 넣는 것만 추가입니다.
- 번역 전에 그 파일의 영어 관용 표현, 은유, 의인화, 지시어를 먼저 뽑아 "한국어 소프트웨어 설명서라면 이 동작을 무엇이라고 부르는가"를 정합니다. 여러 파일에 반복되는 것은 용어집에 있습니다. 독자는 스크린리더로 한 번 듣고 따라 하는 사람이므로, 문장마다 다음을 확인합니다: 영어를 모르고 한 번 들어도 누가 무엇을 하는지 알 수 있는가, 타동사에 목적어가 있는가, 지시어가 가리키는 명사가 가까이 있는가.
- 영어 지시어와 대명사(it, its, that, this, one, ones, that kind of)는 한국어 지시어("그것", "그 X", "하나")로 옮기지 않는 것이 기본입니다. 가리키는 명사를 쓰거나, 문맥으로 분명하면 생략합니다. "그 X"를 남기는 것은 바로 앞 구절의 명사를 가리켜 한 번 들어도 분명할 때뿐입니다. "모듈에서 Enter를 누르면 그 모듈의 화면이"처럼 같은 문장에서 명사를 되풀이하지 않고 "모듈 화면이"로 줄입니다. 예: "그 종류의 대상에 사용할 수 있는 템플릿"(원문 for that kind of object)은 지시어와 "대상"을 함께 고쳐야 합니다.
- 일반 명사 object, thing, entry, giver를 "대상"으로 옮기지 않습니다. 이 설명서에서 "대상"은 target(대상 지정)만 뜻하고, object는 화면 문구대로 "개체"입니다.
- 파일 첫 줄에 `<!-- source: docs/src/user/en/<경로> @ <커밋> -->`로 번역한 원문 커밋을 적습니다.

### 원본이 바뀌었을 때

위 `## upstream 업데이트 절차`로 문자열을 먼저 맞춘 다음, 원문이 바뀐 파일만 바뀐 곳을 번역합니다. 파일 전체를 다시 번역하지 않습니다.

1. 바뀐 영어 설명서 파일을 찾습니다: `git -C ../wowvision-ko/WowVision diff --stat <이전 태그> <새 태그> -- docs/src/user/en`.
2. 파일마다 `uv run python -m tools.manual diff <상대경로>`로 바뀐 영어 원문을 봅니다. 상대경로는 `docs/src/user/en` 기준입니다(예: `basics/interface.md`).
3. 바뀐 곳만 이 문서의 규칙대로 번역하고, 파일 첫 줄의 `<!-- source: ... @ <커밋> -->`을 새 원문 커밋으로 바꿉니다. 바꾸지 않으면 `manual diff`가 같은 차이를 계속 보여 줍니다.
4. `uv run python -m tools.manual check`로 구조와 낱말을 검사합니다.
5. WowVision `ko`에 커밋하고 push한 뒤 설명서를 배포합니다(`docs/builds.md` `## 한국어 설명서 배포`).

## 낱말 표

설명서와 안내문에서 왼쪽 낱말 대신 오른쪽 낱말을 씁니다. 기준은 사전에 있는 말인지가 아니라 읽는 사람이 실제로 쓰는 말인지입니다. 게임 공식 용어, 화면 문구 인용, 버튼 이름은 실물 그대로 둡니다.

| 쓰지 않는 말 | 쓰는 말 |
|--------------|---------|
| 갱신 | 업데이트 |
| 바꾸다(사람이 설정이나 값을 바꾸는 것) | 변경하다 |
| 쓰다(기능이나 키를 쓰는 것) | 사용하다 |
| 뜨다, 떠 있다(프로그램이) | 실행되다, 실행된 |
| 배정 | 할당 |
| 한 단계 뒤로(메뉴나 화면 계층) | 이전 단계로 |
| 나뉘다(구분의 뜻) | 구분되다, 구분하다 |
| 들어가다(포함의 뜻) | 포함되다 |
| 링크를 켜다 | 링크를 클릭하다 |
| 설치기(installer) | 설치 프로그램 |
| 글 파일 | 파일 |
| 방위 | 방향 |
| 거절(내려받기나 설치를 하지 않기로 한 것) | 취소 |
| 줄이 생김 | 추가됨 |

영어 낱말에 "-기"를 붙여 행위자 이름을 만들지 않습니다(installer를 "설치기"로 옮기지 않습니다).
