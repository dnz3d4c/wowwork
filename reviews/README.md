# 번역 검수 기록

WowVision 한국어판 1.0의 번역 검수 기록입니다. 회차마다 무엇을 검수했고 무엇이 바뀌었는지 남깁니다. 검수 방식 전체는 `docs/review-process.md`에 있습니다.

## 용어

- 교차 판정: 번역자가 반박한 지적을 Claude 판정자와 GPT 판정자가 각각 판정하고, 둘의 결론이 같을 때만 확정하는 방식입니다. 커밋 메시지에서는 "두 회사 판정"이라고도 불렀습니다.
- 판정 갈림: 교차 판정에서 두 판정자의 결론이 달랐던 건수입니다.
- 회귀 확인: 지적을 반영한 뒤, 고친 문장에 새 문제가 생기지 않았는지 다시 평가하는 단계입니다.
- 오류 심기 검증: 일부러 오류를 심은 번역을 평가자에게 주고, 몇 개를 찾는지 재서 평가 방식 자체를 검증하는 단계입니다.
- 페르소나 평가: 평가자에게 처음 쓰는 사람, 숙련자 같은 가상 독자 역할을 맡긴 평가입니다.
- 쪽: 설명서의 마크다운 파일 하나입니다.

## 지운 파일 꺼내기

2026-11-19에 평가자 입력과 출력 같은 중간 파일 5,468개(약 95MB)를 최신본에서 지웠습니다. 지운 파일은 커밋 `8be41d2`에 모두 남아 있습니다. 문서가 이 폴더의 회차나 파일을 근거로 가리키는데 최신본에 없으면, 그 커밋에서 꺼냅니다.

    git checkout 8be41d2 -- reviews/2026-11-05-manual

최신본에 남긴 파일은 다음 세 종류입니다.

- 사람이 읽는 기록: 모든 `.md`(보고서, 메모), `.tsv`(반영 목록, 사용자 결정), `.txt`(바뀐 내용, 채점 결과)
- 현행 문서가 파일 이름으로 인용하는 JSON 4개: `2026-11-05-manual/escalations.json`, `2026-11-05-manual-regression/upstream-raw.json`, `2026-11-06-final-ui/result.json`, `2026-11-09-ui-main-merge/batch-01/gpt-terminology-recheck.json`
- 대표 사례 2개(아래 `## 대표 사례`)

중간 파일만 있던 회차는 폴더째 최신본에서 빠졌습니다. 그런 회차도 아래 회차 목록에는 있습니다.

## 대표 사례

한 회차가 처음부터 끝까지 어떻게 흘러가는지 보려면 다음 두 곳을 엽니다.

UI 문자열은 `2026-11-14-ui-v1.0.3/`을 다음 순서로 엽니다.

1. `batches/`: 평가 묶음
2. `batch-01/`: Claude 평가자와 GPT 평가자가 관점별로 낸 지적, 번역자의 반박(`rebut.json`)
3. `full-result.json`: 판정 결과
4. `apply.tsv`: 반영 목록
5. `regression-1/`: 회귀 확인

같은 폴더의 `vessel-*`은 배와 비행선 이름을 따로 평가한 묶음입니다. 교차 판정(`judge-*`)까지 거친 예입니다.

설명서는 `2026-11-14-manual-v1.0.3/reference/keybindings/`를 다음 순서로 엽니다.

1. `*-input-*`: 관점별 평가자에게 준 입력. 이름에 `input`이 없는 같은 이름의 파일이 평가자의 출력입니다
2. `rebut.json`: 번역자의 반박
3. `judge-*`, `judged.json`: 교차 판정
4. `fix.json`: 수정

같은 쪽의 회귀 확인은 `2026-11-14-manual-v1.0.3/regression-1/reference/keybindings/`에 있고, 회차 전체 결과는 `2026-11-14-manual-v1.0.3/manual-result.json`입니다.
